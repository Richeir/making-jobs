# ✍️ 纸上手撕代码

> 门票里的门票。这一项没过，后面的作品、AI 协作能力、业务纵深，
> 面试官根本没机会听你讲。

## 为什么它进面试

招聘方保留纸笔轮不是因为怀旧，是因为它是**成本最低、可横向比较**的能力代理指标：
三十个人同一天交卷，谁在硬编、谁在套模板、谁真的理解，当场分层。

它考的不是"记不记得解法"，是三件 AI 替不掉的事：

1. **在没有补全的环境里保持思路连续**——离开 IDE 就写不下去，说明你从未真正拥有那段代码；
2. **自己就是编译器**——没有测试框架、没有运行器，你要口头 trace 出自己的 bug；
3. **把权衡讲清楚**——为什么用这个结构、这里为什么是 O(n log n)。

## 核心动作

### 固定一套写法，别每次现场选

二分只写一种（左闭右闭），链表题永远先画三个指针，树题先说清"我定义这个函数返回什么"。
**在纸上，肌肉记忆就是正确率。** 现场做设计的代价是错一个边界就整题崩。

### 写完先 trace，再说话

拿题目给的最小样例，逐行标变量。面试官最在意的动作就是这个——
你主动 trace，说明你知道"写完不等于写对"。跳过这步的人，后面被追问一句就露底。

### 每个结构都要能徒手实现

不是"会用"，是纸上从零写出来且不查：

| 必须徒手 | 检验标准 |
| --- | --- |
| 链表反转、快慢指针找中点/判环 | 指针顺序写错就断链，能一次写对 |
| 二叉树三种遍历（递归 + 迭代） | 迭代版用栈，能说清栈里存的是什么 |
| BFS / DFS 网格题 |  visited 时机正确，不重复入队 |
| 堆与 Top-K | 会手写 sift-down，不等库 |
| 并查集（带路径压缩） | 两分钟写完，能解释均摊近似 O(1) |
| 拓扑排序 | 能说出怎么检测环 |
| LRU / LFU | 哈希 + 双向链表，一次写对不返工 |

### 复杂度要带常数项判断

能说清"这里渐近同阶，但常数项差 10 倍"的时刻——比如缓存局部性、
动态数组扩容的均摊、为什么遍历列方向比行方向慢——这是区分背题和懂题的地方。

## 常见失败

- **"我记得这题"**：换个数据范围或加一个约束就卡住。练习时要主动改条件重做。
- **代码没有失败语义**：输入为 null、为空、越界时怎么办，纸上一个字都没写。
  在纸上，**注释你的假设**就是加分项。
- **递归不判溢出边界**：n = 10⁵ 时链式递归会炸栈，说不出来就是没想过。
- **写完就交付**：不 trace、不测样例。这是当场出局最常见的一条。
- **只刷题不写原理**：题做出来但被追问"为什么快排会退化"就哑火——笔试只是入场，追问才是决定项。

## 证据怎么准备

- **错题本**：每题记"当时卡在哪 + 正确的不变式是什么"，考前全部重做一遍。
  这本东西本身就是可展示的证据，面试聊到失败经历时它比话术可信。
- **计时记录**：20 分钟内 medium 正确的截图/照片，攒 20 题的连续记录。
- **模拟录像**：每周 2 次纯纸笔模拟，无 IDE、无补全、无 AI，写完自己当编译器逐行 trace。
- **手写一遍基础设施**：内存分配器 / 线程池 / 简易 RPC / 一致性哈希。
  理解收益高于多刷 50 题，而且它同时是 2.2（工程实践）的证据。
